# 操作流程

## 1. 先定义问题，而不是先下载

记录研究对象、核心问题、时间范围、地区、语言和学习目的。关键词应包括中英文、同义词及方法词。例如：财政压力 / fiscal stress / fiscal pressure，公共服务 / public service provision。

首次检索同时找三类文献：帮助入门的综述、建立基础的经典研究、回答具体问题的近期研究。不要只按年份或引用量筛选。

## 2. 从哪里找

| 来源 | 用途 | 需要核对 |
|---|---|---|
| [Google Scholar](https://scholar.google.com/) | 跨学科检索、追踪引用与其他版本 | 结果可能混合预印本、正式论文和重复版本 |
| [Crossref](https://search.crossref.org/) | 核对 DOI 和出版信息 | 元数据不等于全文或质量认证 |
| 期刊、出版商与学术会议官网 | 核对正式发表或录用状态 | 主刊、主会、增刊、Workshop 等不可混称 |
| [RePEc / IDEAS](https://ideas.repec.org/) | 经济学文献检索 | 工作论文和正式发表版本的对应关系 |
| [NBER](https://www.nber.org/papers)、[CEPR](https://cepr.org/publications/discussion-papers)、[SSRN](https://www.ssrn.com/) | 工作论文与研究线索 | 工作论文不自动等于已同行评审 |
| 作者主页、大学机构仓储、学校图书馆 | 公开稿、接受稿或机构订阅全文 | 稿件版本、访问权限和页面更新日期 |
| [scholar.edu.cn](https://scholar.edu.cn/) | 学术站点导航的可选入口 | 导航或浏览器不能替代原站授权 |

财政学研究通常还需明确财政层级、制度背景和统计口径。其他领域应补充其专业数据库，不必机械套用经济学来源。

## 3. 什么时候下载

默认顺序：检索题录 → 摘要初筛 → 获取需要的正文 → 全文评审 → 精读。

- **初筛阶段**：保存标题、作者、年份、DOI、出处和摘要，不必批量下载。
- **准备质量审查或精读时**：必须获得足够完整的正文，包括影响结论的附录、方法或补充材料。
- **网页全文可读时**：可直接分析，记录 URL、访问日期、章节和表号；无需为了流程完整而强行下载 PDF。
- **需要离线阅读、稳定页码或 PDF 批注时**：下载并关联到 Zotero。
- **定期跟踪时**：建议每周检索一次，先去重、筛选，再补全文。仓库本身没有建立定时任务。

## 4. 如何获取与提取信息

推荐依次使用：数据库提供的 BibTeX/RIS 导出、DOI 元数据解析、Zotero Connector、可用的正式 API、公开网页信息提取。具体服务的接口、限额和使用要求以原站说明为准。

网页提取的基本步骤：

1. 打开搜索或来源页面，记录检索式、筛选条件和访问日期。
2. 读取可见结果，提取标题、作者、年份、摘要及落地页链接。
3. 进入期刊或会议正式页面，核对发表状态；不能只信搜索摘要。
4. 解析 DOI 或页面提供的题录元数据；保留原始来源，不猜测缺失字段。
5. 去重：先比较 DOI 等标识符，再比较规范化标题、作者与年份；预印本与发表稿需人工确认版本关系。
6. 需要正文时，读取网页全文，或使用原页面提供的 PDF 链接。
7. 保存每篇的成功、失败和待处理状态，失败项可以单独重试，不能整批反复新增。

这描述的是获取逻辑，**本仓库没有提供通用爬虫代码**。搜索页面与出版平台经常变化，Google Scholar 也不应被假定具有可供本流程随意调用的公共检索 API。遇到验证码、登录或付费页面，应交给用户完成认证或使用其他合法公开版本。

PDF 下载后至少核对文件头 `%PDF-`、能否正常打开、标题与页数；下载到 HTML 错误页不算成功。网页全文也要检查正文、表格、公式和附录是否完整。

## 5. 存到 Zotero

### 手动路径

安装 Zotero 和 Connector；在文献页面用 Connector 保存，或在 Zotero 中用 DOI 等标识符添加。保存后检查题录、附件、目标分类和重复项。也可以导入数据库导出的 RIS/BibTeX。

### 助手协作路径

安装并启用兼容的 Zotero 连接器，按连接器当前文档配置客户端。Zotero 必须运行；先执行只读查询验证，不能把端口响应视为完整验收。

在具备相应能力的 Zotero MCP 中，可用下列逻辑；工具名和参数须以实际工具列表为准：

```text
查询库与分类 → 检查重复 → 优先按标识符解析题录
→ 创建/复用分类 → 保存条目与标签
→ 有全文则关联附件或保留网页来源
→ 再读回条目，核对题录、分类和附件
```

已有 DOI 时优先使用 Zotero 的元数据解析，避免手工填错类型和出版信息。只能从来源网页建条目时，不补造 DOI、期刊卷期或作者。

建议分类：研究主题 / 子问题。会议或期刊、年份、方法使用标签，避免按多个维度创建大量重复目录。

状态分别记录：`摘要初筛`、`全文待获取`、`全文可读`、`待精读`、`已精读`、`需核查`。同一条目只在实际符合时设置对应状态；不能用“已导入”代替全文状态。

## 6. 学习与笔记

Zotero 保存文献，笔记可放在 Zotero 内，也可放入 Obsidian 的 `notes/`，模板放 `templates/`，主题比较放 `index/`。

笔记以 DOI 或 Zotero key 与原条目关联。必须分清原文主张、背景知识、教学解释和个人推断；关键数字与结论保留页码、章节、表号或图号。未读到的部分明确标记。

## 7. 一批任务如何验收

输出总表：候选数、入选数、去重数、题录入库数、全文可读数、PDF 附件数、精读数，以及失败原因。对入库项读回核验，避免“接口返回成功”但分类或附件缺失。

公开分享只提交指南、模板和脱敏日志，不提交账号密钥、登录 Cookie、个人库数据库或无权分发的全文。
